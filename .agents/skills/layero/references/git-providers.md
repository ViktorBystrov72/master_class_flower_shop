# Провайдеры Git

Layero подключает репозитории пяти провайдеров. Все одинаково — в панели:
**Создать проект → Импорт из репозитория**, затем провайдер, репозиторий и
ветка. Прод-ветка по умолчанию — `main`.

| провайдер | как авторизуется | вебхуки |
|---|---|---|
| GitHub | GitHub App — доступ к выбранным репозиториям выдаётся при входе | да, подпись HMAC-SHA256 |
| GitVerse | персональный токен (PAT), API совместим с GitHub | да |
| GitLab | персональный токен | да |
| GitFlic | персональный токен | да |
| SourceCraft | персональный токен | нет — новая версия запускается деплоем из панели или CLI |

## Что происходит при push

```
git push → вебхук провайдера → Layero создаёт деплой с SHA коммита
        → сборщик клонирует, ставит зависимости, собирает
        → артефакты уходят в хранилище, окружение переключается
```

- Push в `main` (прод-ветка) — сборка и **автовыкат в прод**: новый деплой
  становится тем, что посетители видят на адресе проекта.
- Push в любую другую ветку — **превью-окружение** со своим адресом. Это
  единственный способ получить изолированную версию «просто посмотреть»: у
  прямой загрузки CLI флаг `--branch` не даёт превью.
- Подключённый репозиторий не мешает CLI: `npx layero@latest deploy --prod`
  на таком проекте целится в прод-окружение.

## Ограничения

- У GitVerse пока нет превью pull request и статусов коммита; подпись
  вебхука не проверяется, репозиторий клонируется целиком.
- У SourceCraft нет вебхуков: сам по себе push деплой не запускает.
- Свой Git-сервер подключить нельзя — адрес клиента не в списке разрешённых
  источников платформы.
